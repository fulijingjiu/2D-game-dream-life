# 模块化组合规则

## 目标

角色、装备、动作片段、技能规则和视觉特效分别维护。调整一个角色外观，不要求重画技能逻辑；把技能交给另一个合适角色，也不复制整套动作或特效。

## 五个独立模块

| 模块 | 负责什么 | 不负责什么 | 可替换内容 |
| --- | --- | --- | --- |
| 角色模型 | 身体比例、服装、头发、面部、角色个性 | 技能判定和道具效果 | 使用任何兼容同一骨架的角色皮肤 |
| 装备 | 外观、持握点、挂点、武器 / 工具参数 | 角色是谁、何时攻击 | 圆盾、剑、炸弹、绳镖等形制 |
| 动作片段 | 身体姿势和动作先后 | 伤害、冷却、资源和特效 | 待机、跑步、挥砍、格挡、投掷、攀爬、突进 |
| 技能规则 | 输入、状态、判定、位移、资源、冷却和组合窗口 | 具体角色外观和逐帧图 | 盾反、爆炸投掷、钩索、短距突进等能力 |
| 特效 / UI | 刀光、命中特效、投射物、爆炸、地图信息 | 角色骨架动作和技能所有者 | 颜色、形状、播放时机、界面皮肤 |

## 技能装配描述

技能用“需要什么能力 / 装备”描述兼容性，不用角色姓名描述兼容性。例如：

```yaml
ability: shield_parry
requires:
  - equipment: shield
uses_motion:
  - idle_guard
  - shield_raise
  - shield_parry
  - guard_recover
events:
  - perfect_guard: reflect_or_stagger
effects:
  - shield_impact
```

```yaml
ability: hook_traverse
requires:
  - capability: hook_anchor
uses_motion:
  - hook_throw
  - hook_pull
  - airborne_recover
effects:
  - rope_line
```

以上是表达方式示例，不是项目代码或最终数据格式。

## 动作片段复用约定

- 同一骨架上的角色共用基础动作片段；身高、四肢长度差异明显时通过骨骼重定向或单独适配解决，不因角色名称复制技能逻辑。
- 待机可以按角色外观做个性化变体，但它与技能装配相互独立；切换技能不会强迫换成另一角色的待机，退出技能后回到当前角色配置的待机。
- 动作需要盾、剑、工具、绳索时，动作文档说明“装备槽 / 接触点需求”。手持物作为可替换装备图层，不把具体角色外观焊进动作。
- 角色个性可通过待机、呼吸、受击和表情等表现配置；不会默认改写技能的规则或归属。
- 连招是动作片段组合，例如“横斩 → 上挑 → 下劈”。攻击伤害和取消窗口由技能规则决定；动画只提供姿势和时序参考。
- 一个动作允许被多项技能调用；一个技能也可以组合多个动作、投射物和界面反馈。

## 组合示例

以下只是模块拼装示例，不代表固定角色配置：

- **角色配置 A：** 外观 A + A 的待机循环 + 公共跑跳与闪避 + 盾牌装备 + 盾反技能 + 投掷物技能。
- **角色配置 B：** 外观 B + B 的待机循环 + 同一套公共跑跳与闪避 + 绳镖装备 + 钩索技能 + 短距突进技能。
- **角色配置 C：** 外观 C + C 的待机循环 + 同一套公共跑跳与闪避 + 练习剑装备 + 近战连击。

只要满足技能所需的装备 / 身体能力条件，技能即可换装给另一个角色；视觉配置不会自动改写技能效果。

## 什么时候才拆出专用动作

仅当身体结构或装备造成真实差异时才新建适配动作，例如双手巨剑无法沿用单手短剑挥砍，或无手持器官的角色不能沿用常规投掷。专用动作应按条件命名，如“重型双手劈砍”，不要按角色名命名。

## 单动作制作工作流

1. 选择一份动作文档，每次只制作一个动作片段；动作帧最终按一张透明精灵表整理，Blender 中间输出可先保持逐帧 PNG。
2. 分别指定角色外观、装备形制、目标风格和骨架兼容要求；这几项不是一个角色身份绑定包。
3. 主制作路线使用 Blender 共用骨架与动作片段；可用 AI / 手绘参考姿势，但 AI 生成图或视频只作为参考，未检查和修整前不作为正式动作帧。
4. 将手持物、飞行物与特效按图层或独立资源处理。预渲染后的 PNG 不能自动任意换装；只为小样实际演示的外观 / 装备组合输出素材。
5. 按统一锚点检查并修帧，整理帧顺序与动作事件；战斗判定、伤害、冷却和解锁仍由技能规则 / 程序维护。
6. 如果某个外观或骨架不兼容，记录具体适配点并新增明确的动作适配，不要按角色姓名复制整套技能规则。

## 文档维护规则

- 公共动作放在 `动作/基础移动` 或 `动作/近战`，不以某个角色命名。
- 依赖道具的动作按功能放进 `防御`、`投掷与爆破`、`钩索攀爬` 等目录。
- 角色文档只描述外观配置和故事，不列出排他技能表。
- 技能总览记录解锁来源与使用兼容条件两列；解锁来源不能被解释为使用者锁定。

## 序列帧骨架契约

- 同一组基础动作共享 `Rig_Hero` 骨架名与挂点名；当前小样横斩使用 `Spine`、`Pelvis`、`Arm_Sword`、`Hand_Sword` 和 `Scarf_Tail`。
- 模型部件按身体区域挂骨骼，装备挂 `Hand_Sword` 等装备挂点；替换模型时保留骨骼名称和朝向，避免按角色名复制动作。
- 原始 PNG 序列会把当前外观和装备烘焙到画面。需要运行时换装时，分别导出人物层、装备层和特效层，再由 Godot 合成；不要把整张已渲染 PNG 当成可随意换装的模型。
- 横斩的骨架、帧数、画布和导出设置见项目小样内的《角色建模与序列帧规范》；命中帧只是动作参考，实际攻击判定继续放在技能规则中。
