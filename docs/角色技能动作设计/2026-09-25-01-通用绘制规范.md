# 通用绘制规范

此规范适用于本目录的每份单动作序列帧图。动作片段不归某个角色专有；制作时将可替换的角色外观与动作片段组合。

> **2026-09-27 路线变更。** 现行主干不再是 Blender 2.5D 分件渲染，而是**由 imagegen 逐张生成完整角色帧**，
> 交给 `prototype/2d_pipeline/v4/build_sequence.py` 量脚底对齐、审计一致性并打包成 Godot 序列。
> AI 输出**就是**正式帧的来源，不再“只作参考”；代价见文末“当前路线的已知短板”。
> CSP / Pixelorama 仍用于手工修帧。Blender 路线的产物（V1/V2/V3）已于 2026-09-27 删除，
> 只留在文档叙述里，可从 git 提交 `ccd0925` 取回。
> 动作文档里的编号表示**动作关键姿势的先后顺序**，是首轮制作参考，不是锁定的最终帧数。

## 组合边界

- **角色外观层：** 身体、服装、发型和体型，取自角色视觉锚点或后续定稿模型。
- **装备层：** 由装备定义握持点、挂点、长度和形状；动作稿描述身体怎样运动，不把某个角色的武器形状写进动作定义。
- **动作层：** 待机、跑动、挥砍、格挡、投掷、攀爬等可独立复用的姿势序列。
- **技能层：** 决定什么时候播放哪些动作、何时产生攻击判定、是否移动或消耗资源；技能可组合一个或多个动作片段。
- **效果层：** 投射物、刀光、冲击、残影、爆炸等独立于角色动作；根据技能事件触发。

只有动作确实依赖持盾、握持工具、可抓墙等条件时，才声明装备 / 身体能力兼容标签。标签约束动作条件，不约束角色姓名。

## 单张序列帧图规格

- 每个动作单独一张横向精灵表；背景透明；只出现指定角色、该动作所需的手持物和该动作特效。
- 默认按统一角色比例和脚底 / 锚点基准绘制；角色占格高约 72–84%。项目确定实际像素密度后，再统一格子尺寸；武器可超出身体轮廓但尽量不越过格边。
- 关键姿势从左到右排列，格间留清晰空隙，不加边框、编号、文字、箭头、地面、场景或装饰性 UI。可根据动作需要合并相近姿势或补充过渡帧。
- 透明底上不要绘制投影背景。需要尘土、刀光、绳索、爆炸、盾光或残影时，按动作说明单独作为效果图层呈现，不能遮住角色关键姿势。
- 统一为横版游戏侧视图，角色面向右。除非动作明确要求转身，否则脸、胸口和脚的朝向连续一致。左向版本之后可水平翻转。
- 同一动作所有帧必须保持角色身高、头身比、服装、发型、装备颜色和线条风格一致；只改变动作姿势，不改变造型。

## 动作节奏

通常按「预备 / 蓄力 → 发力 → 命中或释放 → 收势 → 回到可衔接姿势」排列。循环动作要让末帧自然接回首帧；一次性动作最后一帧要能接待机、奔跑、跳跃或下一攻击。

**不规定统一播放速度、停顿时长或最终帧数。** 每份动作稿列出的是动作节拍和关键姿势；预备、发力、命中 / 释放、收势的时间比例按角色重量、技能手感和实机观感调整。循环可增减中间帧；强调冲击的姿势可适当停留，轻快动作则缩短过渡。攻击的有效判定时机只标注动作阶段，最终具体时点需配合实机手感调整；特效不是攻击判定本身。

## 通用序列帧制作简报

本简报可用于 imagegen 逐张出帧（现行）、Blender 动作与渲染、CSP / Pixelorama 手绘修帧。无论哪种来源，输出都必须检查角色一致性、手脚结构、装备位置、脚底锚点与帧间连贯性才进入导出；现行流程把这一步做成了自动门禁，见“当前路线的已知短板”。

> 制作一张游戏用横版 2D 角色序列帧图，不是多张独立插画。按动作文档中的关键姿势和动作方向顺序排列在单行透明网格中；关键姿势数量是制作参考，可按动作连贯性补充必要过渡姿势，不要擅自加入新的动作阶段。所有格保持同一角色比例、同一侧视角和同一基准线。角色外观使用本次指定的可替换角色模型，动作按该文档执行，装备仅采用本次指定的装备形制。格子之间留空，不添加文字、序号、背景、边框、额外角色或多余物件。只画动作所需主体、装备和分层特效。网格表达姿势顺序，不代表播放速度或每格持续时间。现行路线一次生成一个姿势的完整帧（单帧、透明底、同一角色描述逐字复用），再交给脚本对齐排布，不要求模型一次画出一整行精灵表。

## 绘制验收

1. 缩小到游戏实际显示尺寸，仍能看清动作方向和装备轮廓。
2. 快速逐格播放时，身体重心有连续变化，没有无因瞬移或服饰跳变。
3. 起手、攻击 / 释放点、收势等关键阶段都有读得清楚的姿势；可按动作需要增减姿势。
4. 每帧脚底 / 锚点位置有意图：站立动作不漂浮，跳跃动作明确离地，攀爬动作明确抓住墙面或锚点。
5. 没有加入声音图标、声波、字幕或声音效果设计。

## 现行导出规格

以已认可的横斩小样为准，全部由 `prototype/2d_pipeline/v4/build_sequence.py` 固定：

- 画布 384×256，根点 (176, 246)；脚底基线由脚本在源图上自动量取，不手填。
- 横斩 8 帧；第 8 帧是第 1 帧的字节复制，用于循环归位，所以只有 01–07 是独立样本。
- 每帧时长与 `hit` 事件（第 5 帧）写在 `v4/godot/assets/manifest.json`，不硬编码进场景。
- 导出用硬 alpha 保证游戏内边缘锐利；源 RGBA 原图不改动，全部保留在 `v4/source/`。

## 制作期一致性门禁

`build_sequence.py` 在导出前对 01–07 逐帧量：平均色块宽、头带顶到脚底的身体高、内容包围盒、是否贴到源图边缘、与首帧的颜色分布距离，结果写 `v4/preview/2026-09-26-一致性检查.json`。加 `--strict` 时任何告警都会让构建以 1 退出。当前每次构建稳定报 8 条告警。

## 当前路线的已知短板

如实记录，别当成已解决：

1. **imagegen 出的不是像素画。** 源图相邻像素严格相同的比例只有 4%–15%，与高斯模糊后的图无法区分；平均色块宽 1.02–1.05 px，而 1536→384 的导出需要 4 px。提示词里写 “chunky pixel clusters” 不落到数据上。
2. **色板仍未定稿。** 项目历史上从未声明过色板；现有 22 色候选见 `v4/config/palette.candidate.json` 和[角色视觉锚点](2026-09-25-02-角色视觉锚点.md)。注意方向：**加色会让图更不像像素画**，平均色块宽随色数单调下降（12 色 4.06 → 24 色 2.01 → 40 色 1.69）。
3. **武器被烘进整帧。** V3 的 `body / weapon / hands / fx` 分层导出能力在 V4 丢失，运行时无法单独隐藏或替换武器，换装分层要重做。
4. **帧 06 内容被源图左边裁掉**，一致性门禁能查出来，但需要重新生成或扩画布，尚未处理。
5. 脚底对齐是自动量取的，源图出血只报警不修复。
