# 通用绘制规范

此规范适用于本目录的每份单动作序列帧图。动作片段不归某个角色专有；制作时将可替换的角色外观与动作片段组合。当前主要验证 Blender 3D 制作、固定镜头导出 2D 帧的 2.5D 路线；CSP / Pixelorama 可修整帧图，AI 只可作为概念或动作参考。动作文档里的编号表示**动作关键姿势的先后顺序**，是首轮制作参考，不是锁定的最终帧数。

## 组合边界

- **角色外观层：** 身体、服装、发型和体型，取自角色视觉锚点或后续定稿模型。
- **装备层：** 由装备定义握持点、挂点、长度和形状；动作稿描述身体怎样运动，不把某个角色的武器形状写进动作定义。
- **动作层：** 待机、跑动、挥砍、格挡、投掷、攀爬等可独立复用的姿势序列。
- **技能层：** 决定什么时候播放哪些动作、何时产生攻击判定、是否移动或消耗资源；技能可组合一个或多个动作片段。
- **效果层：** 投射物、刀光、冲击、残影、爆炸等独立于角色动作；根据技能事件触发。

只有动作确实依赖持盾、握持工具、可抓墙等条件时，才声明装备 / 身体能力兼容标签。标签约束动作条件，不约束角色姓名。

## 单张序列帧图规格

- 每个动作单独一张横向精灵表；背景透明；只出现指定角色、该动作所需的手持物和该动作特效。
- 默认按统一角色比例和脚底 / 锚点基准绘制；角色占格高约 72–84%。项目确定实际像素密度后，再统一格子尺寸；武器可超出身体轮廓但尽量不越过格边。
- 关键姿势从左到右排列，格间留清晰空隙，不加边框、编号、文字、箭头、地面、场景或装饰性 UI。可根据动作需要合并相近姿势或补充过渡帧。
- 透明底上不要绘制投影背景。需要尘土、刀光、绳索、爆炸、盾光或残影时，按动作说明单独作为效果图层呈现，不能遮住角色关键姿势。
- 统一为横版游戏侧视图，角色面向右。除非动作明确要求转身，否则脸、胸口和脚的朝向连续一致。左向版本之后可水平翻转。
- 同一动作所有帧必须保持角色身高、头身比、服装、发型、装备颜色和线条风格一致；只改变动作姿势，不改变造型。

## 动作节奏

通常按「预备 / 蓄力 → 发力 → 命中或释放 → 收势 → 回到可衔接姿势」排列。循环动作要让末帧自然接回首帧；一次性动作最后一帧要能接待机、奔跑、跳跃或下一攻击。

**不规定统一播放速度、停顿时长或最终帧数。** 每份动作稿列出的是动作节拍和关键姿势；预备、发力、命中 / 释放、收势的时间比例按角色重量、技能手感和实机观感调整。循环可增减中间帧；强调冲击的姿势可适当停留，轻快动作则缩短过渡。攻击的有效判定时机只标注动作阶段，最终具体时点需配合实机手感调整；特效不是攻击判定本身。

## 通用序列帧制作简报

本简报可用于 Blender 动作与渲染、CSP / Pixelorama 手绘修帧，也可作为 AI 生成概念参考的提示。若使用 AI，输出先视为参考稿；必须检查角色一致性、手脚结构、装备位置、脚底锚点与帧间连贯性，再决定是否重绘或修帧。

> 制作一张游戏用横版 2D 角色序列帧图，不是多张独立插画。按动作文档中的关键姿势和动作方向顺序排列在单行透明网格中；关键姿势数量是制作参考，可按动作连贯性补充必要过渡姿势，不要擅自加入新的动作阶段。所有格保持同一角色比例、同一侧视角和同一基准线。角色外观使用本次指定的可替换角色模型，动作按该文档执行，装备仅采用本次指定的装备形制。格子之间留空，不添加文字、序号、背景、边框、额外角色或多余物件。只画动作所需主体、装备和分层特效。网格表达姿势顺序，不代表播放速度或每格持续时间。Blender 路线先导出连续 PNG 帧，再按需要排成精灵表。

## 绘制验收

1. 缩小到游戏实际显示尺寸，仍能看清动作方向和装备轮廓。
2. 快速逐格播放时，身体重心有连续变化，没有无因瞬移或服饰跳变。
3. 起手、攻击 / 释放点、收势等关键阶段都有读得清楚的姿势；可按动作需要增减姿势。
4. 每帧脚底 / 锚点位置有意图：站立动作不漂浮，跳跃动作明确离地，攀爬动作明确抓住墙面或锚点。
5. 没有加入声音图标、声波、字幕或声音效果设计。
