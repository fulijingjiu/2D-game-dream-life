# 序列帧小样实施方案

> 更新于 2026-09-26：已按后续确认的最小范围，完成一名角色、一把剑、待机和完整横斩的 V3 样板。入口见 [横斩样板完成记录](2026-09-26-横斩样板完成记录.md)。下文两套外观、奔跑、盾反属于后续扩展计划，本轮尚未实现；不包含声音。

> 环境状态（2026-09-26）：Blender 5.0.1 与 Godot 4.7.2 已实际导出和加载 V3 素材。AI 分件由内置 imagegen 生成；模型为带真实骨架的 2.5D 贴图分件。动作以 Blender 骨架和独立配置为准。Pixelorama / CSP 与本地 AI 模型不是本轮依赖。

## 1. 小样目标

验证以下链路能否满足本项目的视觉与玩法需要：

**角色设定 / 动作参考 → Blender 共用骨架与动作片段 → 逐帧渲染为 2D 素材 → 自动整理序列帧 / 图集 → Godot 游戏内播放与操作验证。**

主要验证三个问题：

1. 同一个动作能否在不同角色外观上复用。
2. 技能动作能否作为独立模块装配给满足条件的角色，而不依赖角色姓名。
3. 3D 渲染成像素风帧后，动作轮廓、稳定性和打击感是否达到预期。

## 2. 小样范围

### 场景

- 一个固定镜头的简易训练场，只用于看清角色脚底、武器轨迹和帧播放效果。
- 可移动角色、切换外观、播放基础动作和一项技能动作。
- 不做敌人 AI、正式关卡、成长系统、剧情、存档或声音。

### 角色与动作

- **一套基础骨架**，用于相同骨架比例的可替换外观。
- **两种外观配置**：先做一个基础外观，再做一个剪影 / 配色明显不同但骨架兼容的外观。
- **公共动作片段**：待机、奔跑、横斩。
- **技能动作片段**：举盾 / 盾反，作为需要盾牌装备条件的独立动作模块。
- **装备配置**：近战武器与盾牌作为独立挂件 / 手持物，不合并进角色身份。

两种角色外观都应能调用公共动作；盾反是否可用由盾牌装备或技能配置决定，而不是由角色名称决定。由于最终运行素材是预渲染帧，小样只渲染实际用于演示的外观 / 装备组合，不先制作所有排列组合。

## 3. 建议工具

| 环节 | 工具 | 用途 |
| --- | --- | --- |
| 2D 概念和手工修帧 | Pixelorama（可选；CSP 也可） | 检查帧序、修正渲染瑕疵、需要时手工重绘关键帧 |
| 建模、绑定和动画 | Blender | 建简化角色、共用骨架、挂接装备、制作动作片段并逐帧渲染 |
| AI 辅助 | ComfyUI 工作流中的图生视频 / 姿势参考模型（可选） | 生成动作节奏或姿态参考，不直接作为最终 sprite sheet |
| 运行时预览 | Godot 4.7.2 + GDScript | 加载 `SpriteFrames`，测试动作播放、状态切换和技能调用 |
| 素材整理 | Blender Python / 普通 Python 脚本 | 批量导帧、统一锚点、生成图集和帧事件清单 |

Blender 支持骨骼绑定与模型变形；Godot 提供专用 2D 渲染、物理与场景工作流，可用 `AnimatedSprite2D` / `SpriteFrames` 播放单张帧图或精灵表，也可用 `AnimationPlayer` 管理更复杂的动画。[本地 Blender 骨架说明](参考资料/01_动作制作与绘图/2026-09-25-Blender骨骼入门.html) [本地 Godot 2D 入门](参考资料/02_Godot游戏接入/2026-09-25-Godot二维入门.html) [本地 Godot 动画教程](参考资料/02_Godot游戏接入/2026-09-25-Godot动画教程.html)

语言建议是 **GDScript**：项目目前处于 2D 玩法探索期，GDScript 与 Godot 场景 / 动画编辑器直接集成，适合快速迭代角色状态和输入逻辑。Godot 也支持 C#；只有在团队已有 C# 经验或确定需要 .NET 生态时再选它。[Godot 官方语言与 2D 引擎说明](https://godotengine.org/)

AI 工具只作为辅助输入：生图、图生视频或深度图可帮助探索角色和动作参考；输出不直接进入正式动作素材，先由 Blender、CSP 或 Pixelorama 检查并修整。小样不要求本地安装 AI 模型；可先使用已有参考图，避免让 AI 环节阻塞动画验证。[ComfyUI 官方文档本地副本](参考资料/03_AI与深度图/2026-09-25-ComfyUI官方文档.html) [Depth Anything V2 官方说明本地副本](参考资料/03_AI与深度图/2026-09-25-DepthAnythingV2官方说明.html)

## 4. 生产步骤

### 阶段 A：冻结小样规格

1. 确认角色侧视方向、统一脚底锚点、画面比例和目标显示尺寸。
2. 定义最低限度的骨骼与装备挂点：根节点、骨盆、胸、头、左右手、左右脚、主手武器挂点、盾牌挂点。
3. 定义动作接口名：`idle`、`run`、`slash_1`、`shield_raise`、`shield_parry`、`recover`。命名描述功能，不写角色姓名。
4. 为攻击动作标记关键阶段（预备、发力、判定窗口、收势）。具体伤害 / 无敌逻辑仍属于运行时代码，不烘焙进图片。

### 阶段 B：角色模型与共用骨架

1. 先按项目设定画侧面简化模型图，确认头身比与外观剪影。
2. 在 Blender 建低细节模型，优先保证侧面轮廓和手脚动作清楚。
3. 完成一套骨架、蒙皮和统一姿势；第二套外观复用骨架或使用骨骼重定向。
4. 近战武器与盾牌分离为可替换模型，通过挂点跟随骨骼。

### 阶段 C：动作与 AI 辅助参考

1. 先制作公共待机、奔跑、横斩，再制作举盾与盾反。
2. AI 可用来探索姿态或提供动作节奏参考；人工筛选关键姿势后，在 Blender 里重新制作可控动画。
3. 每项动作独立保存为可复用 clip；从任一动作退出后都能回到当前角色自己的待机循环。
4. 用同一组公共动作播放两种外观；至少让两种外观都能触发同一套盾反动作，以验证角色与技能解耦。

### 阶段 D：渲染与帧整理

1. 固定侧视正交相机、渲染尺寸、角色脚底锚点和透明背景。
2. 每个动作导出连续 PNG 帧；第一轮只渲染颜色 / Alpha。法线贴图作为可选对照，不作为通过小样的前置条件。
3. 用最近邻缩放 / 低分辨率采样测试像素风格；关闭抗锯齿作为一种对照设置，并检查闪烁和轮廓跳动。
4. 整理脚本统一裁切范围、对齐锚点、检查透明边缘，输出单动作图集与帧时序清单。
5. 用 Pixelorama 或 CSP 手工修复明显的手持物跳动、边缘噪点和关键帧轮廓问题；若没有绘图软件，先记录问题，仍可用 Blender 调姿势后重渲染。

### 阶段 E：Godot 游戏内预览

1. 在仓库内建立独立的 `godot/` 项目目录，先保留现有 Java 示例文件，不让旧空壳限制技术选择。
2. 建立最小可运行场景与地面基线。
3. 用键盘控制移动，并通过 `AnimatedSprite2D` / `SpriteFrames` 播放 `idle`、`run`、`slash_1` 与盾反动作。
4. 提供切换外观与启用 / 禁用盾牌装备的调试入口。
5. 确认每种外观调用动作时，画面动作和装备跟随正确；没有盾牌时盾反技能不可用。
6. 验证图像帧和战斗判定分离：攻击窗口由动作事件数据配置，修改帧速不会改变技能归属或装备规则。

## 5. 交付物

- Blender 源文件：角色模型、骨架、装备挂点与动作 clips。
- 两套角色外观测试配置。
- `idle`、`run`、`slash_1`、`shield_raise`、`shield_parry`、`recover` 的透明 PNG 序列帧 / 图集。
- 图集对应的动作帧时序与锚点数据。
- 一个 Godot 桌面预览场景，用于切换外观、播放动作和验证盾牌条件。
- 像素尺寸对照图：至少比较普通渲染与低分辨率 / 最近邻效果。

## 6. 验收条件

1. 两套兼容骨架的外观能播放同一套公共待机、奔跑和横斩动作。
2. 盾反由装备 / 能力条件控制；换角色外观不会自动改变技能逻辑。
3. 角色脚底位置稳定，循环动作首尾可接，帧尺寸与锚点无明显跳动。
4. 横斩和盾反的关键姿势在最终游戏显示尺寸下仍可辨认。
5. 输出素材能被 Godot 小样加载；图集、帧顺序和事件表对应一致。
6. 若关闭抗锯齿导致严重闪烁，或像素风格不理想，记录对照结果并回到渲染参数 / 后处理调整，不直接扩大资产制作量。

## 7. 风险和应对

- **组合数量扩大：** 预渲染工作流要为实际出现的角色 / 装备 / 动作组合产出帧图。先用两套外观验证共享骨架，再按游戏允许的装配规则批量渲染，避免提前烘焙所有理论组合。
- **动作像 3D 模型缩小图：** 低分辨率本身不会自动得到好看的像素美术；需要控制模型细节、色阶、轮廓和关键帧姿态，并安排人工修整。
- **AI 参考不稳定：** AI 输出不进入正式资源目录；只保存为参考图 / 视频，最终动作以可编辑的 Blender 动画为准。
- **工程仍是 Java 空壳：** 当前 `src/Main.java` 只是控制台示例，未配置构建系统或游戏框架。小样建议新建 Godot 目录进行验证；是否迁移或清理 Java 示例留到小样通过后再决定。

## 8. 方案决策点

小样结束后根据验证结果作选择：

- **通过：** 后续角色和技能按“共享骨架 + 独立动作片段 + 组合所需烘焙帧”扩展。
- **像素闪烁 / 风格不通过：** 先比较手工修帧、Blender 2D / Grease Pencil 或纯手绘关键帧，不扩大 3D 模型数量。
- **换装组合成本过高：** 评估实时 3D 正交渲染或 2D 骨骼分层，保证技能组合无需为大量搭配重复导出整套帧图。
