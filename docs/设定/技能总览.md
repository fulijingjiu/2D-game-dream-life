# 技能总览

本表描述可组合的技能模块，不是角色专属技能清单。角色剧情中的记忆来源只解释玩家从哪里学会能力；解锁之后由玩家 / 配置决定谁装备并使用。现阶段数值、冷却、资源消耗和最终武器规格尚未定。

**2026-10-15：** 烛火消耗跟「解锁记忆来源 / 锚台」，不跟当前皮肤（与[故事框架](故事框架.md)一致）。**Demo 先砍开场远程**；下表远程行仅占位。现行可跑原型 clips：`idle`、`slash`（`prototype/2d_pipeline/v4/`）。里程碑做到哪一步只看故事框架，不在本文另列。

| 解锁记忆来源（非使用者） | 技能 / 动作片段 | 操作表达 | 战斗作用 | 探索 / 交互作用 | 需要的能力 / 装备条件 |
| --- | --- | --- | --- | --- | --- |
| 初始公共操作 | 奔跑、跳跃、落地、闪避 | 方向、跳跃、闪避输入 | 走位、躲避 | 跨越普通平台 | 角色移动骨架；无专属装备条件 |
| 初始公共操作 | 三段近战（横斩、上挑、下劈） | 连续攻击 | 连击输出 | 无 | 近战动作；兼容符合握持点的单手 / 短兵器 |
| 初始公共操作（占位 · **Demo 不做**） | 远程投掷 | 面向目标后投掷 | 远距离牵制 | 无 | 投掷动作；需要可投掷物和对应手部挂点；Demo 砍掉，不排帧 |
| 闻岚记忆解锁 | 举盾 / 完美盾反 | 按住防御 / 合适时机点按 | 承受正面攻击、成功时弹开攻击并制造硬直 | 挡住标记投射机关 | 需要可举起的盾牌；任何匹配角色可装备 |
| 墨九记忆解锁 | 投掷爆炸物 / 主动引爆 | 瞄准后投掷，可主动引爆 | 范围伤害、打断群敌、连锁爆破 | 炸开有裂纹标识的薄弱障碍 | 需要投掷物、投掷槽位和引爆信号；不绑定特定角色 |
| 小禾记忆解锁 | 钩索 / 标记墙攀附 | 锁定锚点发射；在标记墙抓附 | 拉近轻型敌人、抵达空中目标、脱离包围 | 跨断层、攀上标记墙、翻越高台 | 需要钩索挂点 / 可攀附能力；绳索与角色分层 |
| 祁霜记忆解锁 | 短距突进 / 突进后刺击 | 短按位移，成功避开攻击后可接攻击 | 躲避部分攻击、快速贴近并反击 | 越过短距危险区或裂隙 | 需要可执行快速位移；刺击武器通过装备槽配置 |
| 祁霜记忆解锁 | 地图显影 | 满足探索进度后启动 | 不造成伤害 | 显示未探索布局和已发现重点 | UI 表现，不依赖特定角色动作 |

## 装配原则

- “解锁记忆来源”是叙事来源，不代表技能永久绑定该角色的外观。
- **烛火消耗绑定解锁来源对应的记忆锚台**，不绑定当前皮肤：装备闻岚记忆解锁的盾反时，消耗记在闻岚烛上，即使画面是岑持盾。
- 角色能否使用某技能由能力 / 装备条件判断，例如持盾条件、可投掷物槽位或钩索能力；不要按角色姓名写死。
- 角色待机、移动、受击等公共动作由底层状态机复用；技能在需要时调用相应动作片段，并组合独立的逻辑与特效。
- 一项技能可由多个动作片段组成；同一个动作片段可被多项技能或多名角色调用。
- 地图显影属于界面能力，不占用角色战斗动作槽；纯浏览不耗烛，若强化绑定该记忆则记祁霜锚台。

**现行原型已交付的 clip：** `idle`、`slash`。M1 及之后的排帧顺序以故事框架的里程碑表为准。

## M1 五动作链

M1 要补开场教学用的五段公共动作，按状态机衔接：**跑 → 跳 → 落 → 落地**，**闪**可从待机、跑或下落插入。下表是技能侧的动作与 clip 约定；里程碑是否完成只改故事框架。

| 顺序 | 动作 | 动作文档 | clip（约定，尚未导出） |
| --- | --- | --- | --- |
| 1 | 跑 | [奔跑循环](../美术/动作/基础移动/2026-09-25-奔跑循环.md) | `run` |
| 2 | 跳 | [起跳](../美术/动作/基础移动/2026-09-25-起跳.md) | `jump` |
| 3 | 落 | [下落循环](../美术/动作/基础移动/2026-09-25-下落循环.md) | `fall` |
| 4 | 落地 | [落地](../美术/动作/基础移动/2026-09-25-落地.md) | `land` |
| 5 | 闪 | [闪避翻滚](../美术/动作/基础移动/2026-09-25-闪避翻滚.md) | `dodge` |

衔接：跑循环可切起跳；起跳离地后进入下落循环；下落接落地，落地回到 `idle` 或 `run`；闪避结束回 `idle` 或 `run`。`run` / `jump` / `fall` / `land` / `dodge` 都还没有帧，也不在 `v4/godot/assets/manifest.json` 里。

## 动画制作与游戏运行的分工

- 动作文档规定身体姿势、动作顺序和装备接触点；现行主干是 imagegen 逐张生成完整动作帧，由 `v4/build_sequence.py` 对齐、检查、排成每动作一张精灵表（2026-09-27 起，替代原 Blender 共用骨架路线）。
- 角色外观、装备图像与动作片段分开维护。但在现行路线下装备是画进整帧的，运行时换装尚未实现；预渲染素材只需覆盖 Demo 中实际展示的组合，不要为所有理论换装组合提前导帧。
- Godot 负责读取并播放动作帧；移动、攻击判定、资源、冷却、解锁和技能兼容条件由游戏逻辑配置，不烘焙到图像里。
- AI 生图在当前路线里就是正式动作帧的来源，但必须先通过构建脚本的一致性门禁（角色占比、脚底锚点、色块宽、帧间色偏），门禁不通过不导出。手工修帧仍用 CSP / Pixelorama，Blender 保留为备选路线。
