## 2. 必须先拍板的三处矛盾

### 2.1 叙事绑定 vs 技能解耦（最高优先）

- **故事框架**：施展某位同伴的技艺/装备 → 加深对应烛火消耗；回点强化也指向具体锚台。
- **技能总览**：记忆只解释「从哪里学会」；解锁后按装备/能力条件装配，**不按角色姓名写死**。

**修订建议（写入故事框架「禁术与结界规则」+ 技能总览「装配原则」）：**

1. 烛火消耗跟的是**记忆来源/锚台**，不是当前外观皮肤。
2. 玩家装备「闻岚记忆解锁的盾反」时，消耗记在闻岚烛上——即使画面上是岑举着裂纹圆盾。
3. 故事文案继续写「用某人的技艺」；实现文案写「消耗对应记忆锚台」。两边各加一句互指，避免再打架。

### 2.2 色板双基准（美术阻塞）

`角色视觉锚点` 已写明：造型规范里的设计意图色（如芯·绿 `#63A58E`）与 v4 候选板实测色（芯·绿 `#b4be86`）**不能同时当基准**。

**修订建议：** 在视觉锚点「候选色板」节末增加决策栏（二选一，勾选后删另一组为「废案」）：

- A. 以规范色值重生成/量化，候选板作废；
- B. 承认实测候选板，回写 `主角造型与像素制作规范` 第 4 节。

未勾选前，禁止把色板接进 `build_sequence.py` 导出。

### 2.3 Demo 范围 vs 原型可跑范围

故事/玩法 Demo 验收要：禁术开场、回点四烛、基础操作教学、盾反、闻岚关、残响回应、烛火可见变化。

v4 实际只有：**战斗待机 + 横斩** 的帧播放与 hit 事件验证。

**修订建议：**

- 故事框架「Demo 范围」下增一小节 **「原型里程碑」**：M0=横斩样板（已完成）→ M1=基础移动帧（跑/跳/闪避）→ M2=盾反帧+简易判定 → M3=回点四烛 UI 白盒 → M4=闻岚关最小循环。
- 玩法探索「第一关和 Demo 的教学稿」同步引用同一里程碑，避免策划验收按全文 Demo、美术按横斩样板各说各话。

## 4. 建议 @design 对照原型补的缺口（设定侧已标出的）

按 Demo 因果顺序，而非按动作文件夹全量铺开：

1. **定色板**（2.2）→ 否则后续帧会继续双标准。
2. **M1 基础移动**：跑、跳、落地、闪避（故事开场教学刚需；技能总览已有动作稿）。
3. **M2 盾反**：持盾防御 + 持盾反击两份动作稿已在；需与裂纹圆盾识别剪影对齐视觉锚点。
4. **回点四烛 UI**：无序列帧需求，但故事验收依赖「烛火可见变化」——需白盒高度/分层状态（完整→摇晃→微弱→近熄）。
5. **暂缓**：墨九爆破、小禾钩索、祁霜瞬步、地图显影——第一步 Demo 不挡，文档保持草案即可。
