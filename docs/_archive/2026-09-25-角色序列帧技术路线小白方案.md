# 角色序列帧技术路线：零基础入门方案

> 状态：技术路线草案，先用一个小样验证，再决定是否扩展。面向第一次做游戏动画的开发者；不要求会编程、美术或 3D 建模。

> **现状对照（2026-09-27）：本文的结论已被实机验证推翻一次，请当作背景资料读。**
> 小样实际走的路线是 **imagegen 逐张生成完整角色帧 → 脚本对齐、检查、排布 → Godot 播放**，
> 不是本文推荐的 Blender 2.5D。原因是 V3 阶段用 AI 操作 Blender 建模、绑骨、渲染出的横斩，
> 在关节处有形变、武器缺乏实体感，用户判定明显不如 imagegen 直接画完整角色帧；
> 转向过程记录在 [逐张生图动作制作方案](../../prototype/2d_pipeline/2026-09-26-逐张生图动作制作方案.md)，
> 现行验收状态见 [通用绘制规范](../美术/通用绘制规范.md)的路线变更说明和
> [横斩样板完成记录](../原型/横斩样板完成记录.md)。
> 本文仍然有效的部分：序列帧的基本概念、脚底基线与锚点、关键姿势的读法、灰度剪影判读、
> 以及“外观 / 动作 / 技能解耦”这条原则。已经失效的部分：AI 只能做参考图这一条限制，
> 以及“Blender 是主要制作路线”的判断。V1/V2/V3 的 Blender 产物已于 2026-09-27 删除。

## 先用一句话理解

序列帧就像一本快速翻动的小画册：每张图片是一个动作瞬间，游戏按顺序播放这些图片，角色就动起来了。对本项目来说，制作软件负责“做动作和图片”，Godot 负责“在游戏里播放图片和处理操作”。

## 我建议先采用这条路线

**AI 或手绘只做参考图 → Blender 做一套可重复使用的简化角色骨架和动作 → 导出透明 PNG 序列帧 → Pixelorama 或 CSP 检查、修整 → Godot 播放并接入游戏操作。**

这是一条“3D 制作、2D 使用”的 2.5D 路线。玩家最终看到的是 2D 画面；角色和动作在 Blender 里用 3D 骨架制作。这样可以重用跑步、跳跃、挥击等动作，也方便替换角色外观和装备。Blender 能按动画帧逐张输出图像，Godot 能把多张图片作为 2D 动画播放。[Blender 动画基础](https://docs.blender.org/manual/en/5.0/animation/introduction.html) [Blender 动画图像输出](https://docs.blender.org/manual/en/5.0/render/output/properties/output.html) [Godot 2D 动画](https://docs.godotengine.org/en/stable/tutorials/animation/)

## 几条做法，用日常语言比较

| 做法 | 可以把它想成 | 优点 | 初期容易碰到的问题 | 本项目怎么用 |
| --- | --- | --- | --- | --- |
| 手绘逐帧（CSP） | 一张张画翻页动画 | 风格控制最直接，画面表现力强 | 每个新动作都要画很多张；角色、装备变化也会增加绘制量 | 用来修关键帧和小样，不把所有动作都从零手绘作为第一步 |
| AI 生图 / 图生视频 | 请 AI 先给姿势或运动参考 | 方便找造型、构图和动作灵感 | 多帧里脸、衣服、武器、比例可能变化；导出的画面也不一定有透明背景、固定脚底位置或游戏需要的帧数 | 只做概念和动作参考，正式帧由可编辑的制作流程产出 |
| AI 深度图 | 让 AI 猜一张图片里近处和远处 | 可以让静态背景做轻微远近视差 | 它只是“深浅估计”，不是完整 3D 模型；单张图的深度也不能直接变成稳定的角色动作 | 以后可用于背景层次，不作为角色动作方案 |
| Blender 3D 转 2D | 用 3D 木偶摆动作，再从固定方向拍成一张张图 | 一套骨架可复用多种动作；可单独挂武器、盾牌和工具；改姿势比重画整张图方便 | 初次学骨架、材质、灯光和渲染需要一点时间；渲染出来仍要检查轮廓和像素效果 | **作为小样的主要制作路线** |
| 程序 / 2D 骨骼动画 | 把角色拆成身体部件，用“骨头”连接并在游戏里摆动 | 改颜色、换部件和动作参数较方便；不必为每一帧保存一张完整图片 | 关节处可能像纸片或橡皮；像素风的轮廓会变形；要设计拆件和骨骼 | 放在后续备选。Godot 有 2D 骨骼和 Cutout 动画功能，可在小样之后比较。[Godot 动画章节](https://docs.godotengine.org/en/stable/tutorials/animation/) |

## 为什么这次先选 Blender 2.5D

1. **适合动作很多的游戏。** 待机、奔跑、跳跃、攻击和攀爬可以各自保存成独立动作片段。
2. **符合角色与技能解耦。** 外观、动作、装备和技能规则分别处理；“谁能用钩索”由游戏数据决定，不把技能写死在角色名字里。
3. **对新手较容易看出成果。** Blender 可以先用简单形状搭一个木偶，不必先画出完整精美角色；姿势能动、序列帧能播放就是第一阶段成果。
4. **适合当前已有工具。** 项目工作区已有 Godot 4.7.2，电脑也已安装 Blender 5.0.1；先不需要额外安装本地 AI 模型。

## 小样怎么做：只走六步

### 第一步：先选一个动作

先用“待机循环”或“横斩”其中一个，不同时做四个角色和整套技能。查看现有[待机循环动作说明](../美术/动作/基础移动/2026-09-25-待机循环.md)或[横斩动作说明](../美术/动作/近战/2026-09-25-横斩.md)，照着关键姿势做。

### 第二步：做一个简化角色

先用方块、圆柱等简单形状做头、身体、手臂和腿。在 Blender 里给它接一套简易骨架。第一轮先不追求细节，重点看动作是否清楚、脚底是否稳定。Blender 把骨架当作控制角色各部位的“木偶关节”。[Blender 骨架入门](https://docs.blender.org/manual/en/5.0/animation/armatures/bones/introduction.html)

### 第三步：把动作做成可以重播的片段

在 Blender 时间轴摆出几个重要姿势，例如：站稳 → 蓄力 → 挥出 → 收势。动作名称按用途命名，如 `idle`、`run`、`slash`，不要按角色名字命名。武器和盾牌作为单独物件挂在手部位置。

### 第四步：从固定方向拍成 PNG 图片

使用固定的侧面相机，固定角色脚底位置，背景设为透明，输出 PNG 序列。每张图片就是一个游戏帧；PNG 的透明通道可以让游戏背景透出来。不要第一轮就调很多复杂效果，先确认帧没有跳位，动作一眼能看懂。

### 第五步：检查和修整

用 Pixelorama 或 CSP 播放这些帧，检查动作是否连贯、脚底是否抖动、武器是否穿过身体。需要时只修几张最关键的画面。Pixelorama 的官方手册说明了如何把动画导出成多张 PNG 或一张精灵表。[Pixelorama 保存与导出](https://pixelorama.org/user_manual/save_and_export/)

如果你说的“CPA”是 **CSP（Clip Studio Paint，简称 CSP）**，它可以逐张绘制动画、用时间轴检查、开洋葱皮参考前后帧；如果你指的是另一款软件，后续再把链接换成对应工具即可。[CSP 官方动画入门](https://support.clip-studio.com/en-us/faq/articles/20210092)

### 第六步：放进 Godot 试播

把 PNG 帧导入 Godot，用 `AnimatedSprite2D` 播放。游戏里的跳跃、攻击判定、冷却和技能解锁仍由 GDScript 处理；图片只负责呈现动作。Godot 官方 2D 说明和动画教程有从图片帧建立动画的入门内容。[Godot 2D 入门](https://docs.godotengine.org/en/stable/tutorials/2d/introduction_to_2d.html) [Godot 动画入门](https://docs.godotengine.org/en/stable/tutorials/animation/)

## AI 和深度图放在哪里

- **AI 生图 / 图生视频：** 用来探索角色造型、颜色、关键姿势和动作节奏。把结果当参考，不直接把一段视频当成可用的游戏序列帧。
- **AI 深度图：** 等游戏要做有远近层次的背景时，再拿一张背景图试做前、中、后景视差。深度图会估算画面里哪里较近或较远；它不会自动给人物补齐背面、骨骼或连续动作。[Depth Anything V2 项目说明](https://github.com/DepthAnything/Depth-Anything-V2)
- **ComfyUI：** 是把 AI 生成步骤连接起来的可视化工具，适合以后需要重复生成参考图时再学。第一轮不是必需工具，也不需要现在就配置本地模型。[ComfyUI 官方文档](https://docs.comfy.org/)

## 一个关键边界：预渲染的图片仍然有组合成本

Blender 可以重用同一套动作和骨架，但如果角色外观、武器、盾牌都要任意组合，最终每种画面搭配仍可能需要重新渲染。小样先做“一个骨架、两种外观、待机 / 跑步 / 横斩、一个盾牌技能”来验证共享动作；只输出需要演示的搭配，不提前制作所有可能排列。技能规则仍保持独立，避免把某个技能写死在某个角色身上。

## 小样通过标准

- 至少一个动作能从 Blender 导出为透明 PNG 序列，并在 Godot 正常播放。
- 同一个动作能由两种外观播放，脚底不会明显跳动。
- 装备能单独替换；技能是否能用由装备或能力条件决定。
- 最终游戏显示尺寸下，动作轮廓清晰，关键动作阶段看得懂。
- 记录制作一个动作花了多少时间、哪些地方要手修，再决定继续用 Blender、转手绘或试 2D 骨骼动画。

## 术语小抄

- **序列帧：** 按顺序播放的一组图片。
- **精灵表 / Sprite Sheet：** 把许多帧排在同一张大图里，方便游戏读取。
- **骨架 / Rig：** 控制头、身体、手脚等部位的虚拟关节。
- **2.5D：** 制作时借用 3D 的空间和骨架，最终以 2D 画面呈现。
- **深度图：** 用明暗或数值表示画面哪些部分更近、哪些更远；它不是 3D 模型。
- **洋葱皮：** 绘图软件半透明显示前一帧或后一帧，帮助画动作连续。
- **模块化：** 角色外观、装备、动作、技能规则分开，可以按条件组合。
