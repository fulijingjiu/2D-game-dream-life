# 模块化组合规则

## 目标

角色、装备、动作片段、技能规则和视觉特效分别维护。调整一个角色外观，不要求重画技能逻辑；把技能交给另一个合适角色，也不复制整套动作或特效。

## 五个独立模块

| 模块 | 负责什么 | 不负责什么 | 可替换内容 |
| --- | --- | --- | --- |
| 角色模型 | 身体比例、服装、头发、面部、角色个性 | 技能判定和道具效果 | 使用任何兼容同一骨架的角色皮肤 |
| 装备 | 外观、持握点、挂点、武器 / 工具参数 | 角色是谁、何时攻击 | 圆盾、剑、炸弹、绳镖等形制 |
| 动作片段 | 身体姿势和动作先后 | 伤害、冷却、资源和特效 | 待机、跑步、挥砍、格挡、投掷、攀爬、突进 |
| 技能规则 | 输入、状态、判定、位移、资源、冷却和组合窗口 | 具体角色外观和逐帧图 | 盾反、爆炸投掷、钩索、短距突进等能力 |
| 特效 / UI | 刀光、命中特效、投射物、爆炸、地图信息 | 角色骨架动作和技能所有者 | 颜色、形状、播放时机、界面皮肤 |

## 技能装配描述

技能用“需要什么能力 / 装备”描述兼容性，不用角色姓名描述兼容性。例如：

```yaml
ability: shield_parry
requires:
  - equipment: shield
uses_motion:
  - idle_guard
  - shield_raise
  - shield_parry
  - guard_recover
events:
  - perfect_guard: reflect_or_stagger
effects:
  - shield_impact
```

```yaml
ability: hook_traverse
requires:
  - capability: hook_anchor
uses_motion:
  - hook_throw
  - hook_pull
  - airborne_recover
effects:
  - rope_line
```

以上是表达方式示例，不是项目代码或最终数据格式。

## 动作片段复用约定

- 同一骨架上的角色共用基础动作片段；身高、四肢长度差异明显时通过骨骼重定向或单独适配解决，不因角色名称复制技能逻辑。
- 待机可以按角色外观做个性化变体，但它与技能装配相互独立；切换技能不会强迫换成另一角色的待机，退出技能后回到当前角色配置的待机。
- 动作需要盾、剑、工具、绳索时，动作文档说明“装备槽 / 接触点需求”。手持物的目标是独立装备图层；现行帧把装备画进画面，早期装备条件是永久解锁旗标，不做运行时换装。不把具体角色外观焊进动作规则。
- 角色个性可通过待机、呼吸、受击和表情等表现配置；不会默认改写技能的规则或归属。
- 连招是动作片段组合，例如日后的「横斩 → 上挑 → 下劈」。近战 clip 名是 `slash`，旧帧已撤，待按形制图重出；上挑、下劈是后期。攻击伤害和取消窗口由技能规则决定；动画只提供姿势和时序参考。
- 一个动作允许被多项技能调用；一个技能也可以组合多个动作、投射物和界面反馈。

## 组合示例

以下只是模块拼装示例，不代表固定角色配置：

- **角色配置 A：** 外观 A + A 的待机循环 + 公共跑跳与闪避 + 盾牌装备 + 盾反技能 + 投掷物技能。
- **角色配置 B：** 外观 B + B 的待机循环 + 同一套公共跑跳与闪避 + 绳镖装备 + 钩索技能 + 短距突进技能。
- **角色配置 C：** 外观 C + C 的待机循环 + 同一套公共跑跳与闪避 + 练习剑装备 + 近战连击。

只要满足技能所需的装备 / 身体能力条件，技能即可交给另一个满足条件的角色使用；视觉配置不会自动改写技能效果。早期这些条件是永久解锁旗标。

## 什么时候才拆出专用动作

仅当身体结构或装备造成真实差异时才新建适配动作，例如双手巨剑无法沿用单手短剑挥砍，或无手持器官的角色不能沿用常规投掷。专用动作应按条件命名，如“重型双手劈砍”，不要按角色名命名。

## 单动作制作工作流

1. 选择一份动作文档，每次只制作一个动作片段；现行路线一次出一个姿势的完整 PNG，攒齐后由脚本排成一张透明精灵表。
2. 分别指定角色外观、装备形制、目标风格和骨架兼容要求；这几项不是一个角色身份绑定包。
3. **主制作路线是 imagegen 逐张生成完整角色帧**（2026-09-27 起，见
   [通用绘制规范](通用绘制规范.md)的路线变更说明）；Blender 共用骨架路线的产物 V1/V2/V3 已删除。
   AI 输出**可以**作为正式动作帧进入资产目录，但必须先进脚本的一致性门禁（逐帧色块宽、角色占比、脚底锚点、
   同帧间差异），门禁不过不导出。手绘 / CSP / Pixelorama 修帧和 Blender 仍是可用备选，只是不再是主干。
4. 分层要求保留为目标，但**当前 V4 路线做不到**：生成的是完整帧，武器和特效直接烘进画面，
   V3 曾有过的 `body / weapon / hands / fx / composite` 独立图层在 V4 已丢失。早期玩法的「装备条件」是永久解锁旗标，不做运行时换装；
   要换画面上的装备，只能重新逐帧生成该外观 / 装备组合，不能靠运行时叠加。预渲染 PNG 从来不等于可换装模型。
5. 按统一锚点检查并修帧，整理帧顺序与动作事件；战斗判定、伤害、冷却和解锁仍由技能规则 / 程序维护。
6. 如果某个外观或骨架不兼容，记录具体适配点并新增明确的动作适配，不要按角色姓名复制整套技能规则。

## 文档维护规则

- 公共动作放在 `动作/基础移动` 或 `动作/近战`，不以某个角色命名。
- 依赖道具的动作按功能放进 `防御`、`投掷与爆破`、`钩索攀爬` 等目录。
- 角色文档只描述外观配置和故事，不列出排他技能表。
- 技能总览记录解锁来源与使用兼容条件两列；解锁来源不能被解释为使用者锁定。

## 序列帧对齐契约

现行 V4 路线没有骨骼，跨帧对齐靠画布和锚点，不靠骨架名：

- 所有帧共用一张 384×256 画布和同一个脚底根点 `(176, 246)`；根点由脚本按每帧实际像素自动测量后归一到统一基准。
- 帧序号、每帧时长和命中事件写在 `v4/godot/assets/manifest.json`，Godot 按 manifest 播放；动作文档里的编号只是姿势先后顺序。
- 生成的是完整帧，角色外观和装备被烘进画面。早期装备条件是永久解锁旗标，不靠运行时换装。
  不要把整张已渲染 PNG 当成可随意换装的模型。

## 骨架契约（Blender 路线，历史）

以下为 V2/V3 Blender 路线的对齐方式，产物已于 2026-09-27 删除，仅在回到 3D 路线时适用：

- 同一组基础动作共享 `Rig_Hero` 骨架名与挂点名；当时小样横斩使用 `Spine`、`Pelvis`、`Arm_Sword`、`Hand_Sword` 和 `Scarf_Tail`。
- 模型部件按身体区域挂骨骼，装备挂 `Hand_Sword` 等装备挂点；替换模型时保留骨骼名称和朝向，避免按角色名复制动作。
- 横斩的骨架、帧数、画布和导出设置见项目小样内的《角色建模与序列帧规范》；命中帧只是动作参考，实际攻击判定继续放在技能规则中。
