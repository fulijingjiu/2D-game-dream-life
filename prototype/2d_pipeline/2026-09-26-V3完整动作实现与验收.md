## 模型如何调整

在 Blender 打开 `.blend`，选中 `HeroRig`，切换 Pose Mode 调骨骼。时间轴标记 `Slash_01` 至 `Slash_12` 对应导出姿势；切换 Action 到 `Hero_idle` 可查看待机。贴图已经打包，源图集仍单独保留。

模型包含真实 Armature 和蒙皮权重，使用 2.5D 平面贴图网格。头、躯干、四肢采用刚性分件；围巾由两段骨骼弯曲；靴底权重过渡到独立脚掌骨，使脚底保持水平。武器挂在 `hand_r`，手掌在武器之前显示。转到背面需要背向分件，不应任意旋转相机期待完整体积效果。

脚本按配置重建模型，会覆盖本版本 `.blend` 和导出帧。在 Blender 手动修改后，请先“另存为”保留编辑；手改不会自动回写 JSON。修改关节或动作参数后运行脚本，可以重复得到同一套姿势。

## 像素规格与帧节奏

原生画布 **256×192 RGBA**；统一根点 **(112,176)**；所有可见脚底均结束于 y=176 像素边界。Godot 按最近邻放大 3 倍。角色待机可见高度约 148 px；增加横向留白用于蓄力、剑尖和刀光。相机固定，任何帧都不自动裁切。

| 帧 | 阶段 | 时长（毫秒） | Blender 时间轴 |
| --- | --- | ---: | ---: |
| 01 | 待机 | 85 | 1 |
| 02 | 起手 | 65 | 18 |
| 03 | 蓄力 | 75 | 31 |
| 04 | 蓄力峰值 | 90 | 46 |
| 05 | 挥出 | 35 | 64 |
| 06 | 加速 | 30 | 71 |
| 07 | 命中 | 75 | 77 |
| 08 | 跟随 | 40 | 92 |
| 09 | 缓冲 | 50 | 100 |
| 10 | 回收 | 65 | 110 |
| 11 | 归位 | 65 | 123 |
| 12 | 待机衔接 | 85 | 136 |

总时长 **760 ms**。Blender 时间轴采用 200 fps 的 5 ms 刻度，关键帧为 CONSTANT 保持；场景帧范围 1–152。实际可见横斩只有 12 个姿势。待机 4 个姿势，各 180 ms，循环 720 ms。GIF 受格式限制，以累计舍入到 10 ms 的时长预览；Godot 和 HTML 使用原始毫秒数据。

动作事件 `hit` 标记进入第 7 帧，即攻击开始后 380 ms；它是接入战斗系统的时间参考，本轮未实现伤害、敌人或碰撞判定。

## 图层与组合

每帧导出 `body`、`weapon`、`hands`、`fx`、`composite` 五份 PNG。

播放时按照 **body → weapon → hands → fx** 合成。手掌单独置于剑柄之前，避免分层后剑压住手。`composite` 是完整检查图；关闭剑或刀光不会隐藏身体和手。改变剑的外观或长度后，需要重新渲染该组合的武器层；当前导出的另一把武器并不存在。

当前 `body` 中头发与头同贴图、四记忆芯同贴图；它们可通过替换分件图块修改，但尚未支持运行时逐根发束或逐芯换色。角色能力、道具解锁、伤害规则均不写进模型。

## 运行和重建

在仓库内层 `2d-game/` 目录运行：

```bash
blender --background --python prototype/2d_pipeline/v3/blender/build_rig.py
python3 prototype/2d_pipeline/v3/package_preview.py
bash prototype/2d_pipeline/v3/run_demo.sh --headless --editor --import --quit
bash prototype/2d_pipeline/v3/run_demo.sh
```

Godot 按钮可播放、暂停、逐帧、循环、切换剑和特效、切换速度；空格重播，左右方向键逐帧，P 暂停，L 循环，W 武器，F 特效。默认待机，横斩完成后自动回待机。首次运行自动导入资源；重新导出 PNG 后先执行上述导入命令。

无窗口逻辑检查：

```bash
bash prototype/2d_pipeline/v3/run_demo.sh --headless -- --verify
```

## 实测结果与限制

- 12 帧横斩、4 帧待机，五个输出层，共 80 张 PNG；运行程序加载其中 64 张分层图。
- 16 个姿势均为 256×192 RGBA，alpha 为 0 或 255，所有轮廓都留有透明边距；总范围 x=64–205、y=7–176（右下为排他边界）。
- 横斩首尾完全一致，横斩起始与待机首帧完全一致。
- 分层合成与 Blender 完整渲染的可见像素完全一致。alpha=0 下的隐藏 RGB 不参与显示比较。
- 骨骼实际求值位置最大误差小于 0.000001 Blender 单位；手握点与武器挂点误差小于 0.000001；两脚掌位置固定，全部手部目标在关节可达范围内。
- Godot 通过非等时播放、760 ms 后回待机、一次命中事件、重播复位、图层开关、逐帧和循环检查。
- 已逐帧目视检查待机、蓄力、命中和收势，修正了肘部姿势与靴底离地问题。
- 浏览器工具拒绝 `file://` 离线页面自动打开，因此没有完成浏览器交互实测；离线 HTML 文件已生成。Godot 图形窗口未做自动截图验收，程序逻辑通过 headless 检查。

原始检查数据：[模型](v3/preview/rig_checks.json)、[素材](v3/preview/asset_checks.json)、[Godot](v3/preview/godot_checks.json)。本轮是第一套可用的侧视动作样板；贴图在关节处仍保留分件动画的形变特征，尚未逐像素手修，也未验证第二套角色或其他视角。
